**Standing requirement from Edmund, 26 October 2026: document every trial.** This includes previews,
rejected inputs, provider failures, cancellations and negative tests. A trial without usable evidence
does not become a successful result merely because code exists.

The automated record set is [output/trials](../../../output/trials). Each invocation has a UUID file,
written before validation/network work and updated with timestamps, phases, configuration/source hashes,
commands/input references, outcome, artifact links and cost status. Showcase execution, rental-tool
invocations and the two new fixture suites use these records. Existing unrelated test suites/releases
retain their Book entries; this is not a claim to instrument every historic command.

Record the question being tested, exact configuration/revision, hardware/model details (or explicitly
unmeasured), input provenance, commands, expected behavior, observed results, failures/fixes, costs,
cleanup and limitations. Keep raw/private operator artifacts separate from anonymous reviewer files.
No raw credentials, account environment dumps, prompts or provider error bodies belong in this register.
Cost zero requires evidence of no paid use; an unreconciled external bill stays unknown/null.

`started` with no finish is an incomplete/crashed trial requiring investigation, not a pass. Never delete
failed records to make a run look successful. Do not invent missing historic detail retrospectively.
Trial JSON files are local operator material; review/redact them before publishing. Their filesystem
timestamps use UTC; human session notes below use the Nairobi calendar date. Aggregate files under
`output/proof` show the latest suite only; UUID trial files retain earlier invocations.
