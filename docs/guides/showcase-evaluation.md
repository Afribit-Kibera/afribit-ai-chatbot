From the repository root:

```powershell
pnpm --filter @afribit/api showcase:eval
```

The default dry run validates the pack, plan, synthetic cases, contexts and reservation envelope. It
prints hashes and eight planned attempts (four questions × two variants), with no model, database,
pricing or health request. It does not inspect RunPod credentials. The normal config loader can load
`.env`; dry-run requests neither use nor print its keys.

Edit a copy of [showcase-plan.json](../examples/showcase-plan.json). Model names/revisions are
placeholders, not recommendations. Configure at most two candidates with F-018's
[route fields and units](community-compute-policy.md). Endpoints must match `OPENROUTER_BASE_URL` or
`LOCAL_LLM_BASE_URL`. Credentials stay in environment configuration, never the plan. Scoped candidate
models override `LOCAL_LLM_MODEL` for this CLI only; deployed profiles remain unchanged.

Paired variants use identical model, temperature zero, output ceiling and word-limit instruction: a
fair bare instruction versus the full product prompt with frozen supplied passages. The latter includes
language and safety prompting too, so differences cannot be attributed solely to RAG. No live retrieval
selection, account memory, safety post-filter or complete chat workflow is measured. There is no automatic
retry, fallback, paid judge, training, quality winner or meaningful p95. Word count is an instruction;
context, tokens, execution time and evidence size have separate enforced limits.

## Gates before paid execution

The first envelope is at most **USD 10**, including at least **USD 2 held aside**. One dollar is 1,000,000
micro-USD. Declare an upper allowance for non-model charges in `externalChargesMicrousd`: GPU startup,
downloads, idle time, volumes/storage, shutdown delay and applicable fees. An unpriced rental is not
zero-cost merely because the runner and model share localhost.

Remote routes require `upstreamLimitReference`: record the actual upstream account/key ceiling, including
an absent ceiling, and the experiment's separate controls. Prefer a dedicated capped provider key. A
fixed-count text-only API comparison can use conservative persistent request reservations, upstream
`max_price`, bounded input/output and no tools/retry/fallback; record cumulative earlier allowances and
reconcile provider-reported costs/account usage. Do not label an application allowance a provider-enforced
cap. The 27 October trial explicitly used this bounded case without changing the existing uncapped key.
Long-running rentals additionally require the independently verified shutdown mechanism and all-in quote.
This reference is operator evidence, not provider verification.
The runner neither creates nor stops pods and cannot enforce hourly billing. A real quote, lifecycle
watchdog, termination/storage checks and final incremental bill remain required before claiming the $10
was respected. No rental starts when preparing the example.

Use only synthetic/public-approved inputs under ADR 0016. The synthetic flag is a declaration, not a
private-data detector. Review replacement packs/cases yourself; the tool never reads learner tables.
Use authenticated GPU gates and remote TLS. ZDR, tunnels and TLS do not hide prompts from ordinary
endpoint operators or establish a TEE.

After these gates are met, execution syntax is:

```powershell
pnpm --filter @afribit/api showcase:eval --plan D:/path/to/reviewed-plan.json --benchmark D:/path/to/frozen-cases.json --ledger D:/path/to/first-experiment.json --out D:/path/to/private-results --execute
```

The hosted trial used a retained operator script around this runner. Execution requires `--ledger`. Reuse that exact
absolute path across the whole experiment, including failures/restarts. Separate ledgers, accounts or
tools bypass its cap; cumulative accounting and upstream request bounds remain necessary. Different concurrency configurations currently
need separately frozen plans/ledgers and must share the same overall $10 externally, not get $10 each.
Legacy Dataset Lab scripts retain their older budgets and are outside this controller.

## Reservations and recovery

The ledger binds plan, benchmark, loaded pack, source files and inference settings by hash. It reserves
before dispatch and never refunds successful, failed, cancelled, interrupted or missing-cost attempts.
Non-model charges and safety reserve count from the start. Attempt counts persist: re-running a
completed plan cannot dispatch again. Changed frozen inputs are refused rather than given fresh capacity.

An exclusive `.lock` prevents concurrent processes. Cancellation waits for settlement before releasing
it. Crashes, uncertain persisted accounting or overdue cleanup retain the lock: confirm the process is dead, stop/reconcile upstream
work and inspect reservations/bills before deciding recovery. Never automatically remove locks, erase
ledgers or infer refunds from missing completion records. Private temporary files are flushed and
renamed; durability relies on the OS/disk. Administrators can alter these files or bypass application code.

Reported overruns persist a stop. Missing usage never releases capacity; admitted work may finish after
a stop. This is an application allowance, not a vendor invoice guarantee. `maxDurationMs` bounds one
invocation after ledger opening, not rental lifetime, setup or cumulative runtime. Socket cancellation
does not prove provider work/billing stopped.

## Evidence

Each invocation creates a fresh directory:

- `manifest.json`: plan, benchmark, hashes, commit/dirty flag, runtime options and start time. Model
  revision can be declared/unverified; peak memory and rental bill remain null. Source hashes identify
  code without archiving it: retain the exact checkout/patch before external measurements.
- Per-attempt JSON and `operator.json`: model/variant mapping, full/partial outputs, status, first-token
  and full-attempt timing, reported usage/cost, reserved allowance and skipped/cancelled counts. Timing
  includes local admission/transport. Missing cost is not measured zero cost.
- `blind-review.json`: shuffled anonymous IDs, questions, criteria and empty human scores. Share only
  this file with independent scorers; keep mappings separate. Structural identity is omitted, but a model
  might name itself in generated text. Give scorers separate copies and preserve disagreements. There
  is no automatic score aggregation or model selection.

Keep artifacts private pending review. Mode 0600 is requested; Windows directory ACLs determine access.
Record actual hardware, verified digests, quantization, region, memory, reviewers and invoices separately.
One/four-worker fixtures prove scheduling, not GPU or Mesh performance.

`pnpm --filter @afribit/api test:showcase` exercises localhost transports and filesystem controls.
The aggregate [proof](../../output/proof/p4-showcase-runner-proof.json) contains counts and limitations only.
